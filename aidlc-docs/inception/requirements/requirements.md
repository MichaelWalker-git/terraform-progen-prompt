# Requirements — projen-terraform

## Intent Analysis

| Attribute | Assessment |
|---|---|
| **User request** | Build a reusable projen project type that scaffolds governed raw-HCL Terraform repos, porting the linting, security scanning, docs, tests, and GitHub Actions trio from our CDK-TypeScript projen repos. |
| **Request type** | New Project (greenfield) |
| **Scope estimate** | Multiple Components (project-type core, HCL renderers, tooling-config generators, GitHub Actions generators, test-harness wiring) |
| **Complexity estimate** | Moderate–Complex (projen component authoring + faithful reproduction of the self-mutation CI pattern for a non-native project type) |
| **Requirements depth** | Comprehensive |

## Decisions Locked (from verification questions)

| # | Decision | Choice |
|---|---|---|
| Q1 | HCL ownership | **Config-only**: projen owns `versions.tf`, `.tflint.hcl`, tfsec/checkov config, `.terraform-docs.yml`; `main.tf`/`variables.tf`/`outputs.tf` scaffolded once then user-owned |
| Q2 | Security scanner | **Both** tfsec and checkov |
| Q3 | Test framework | **Native `terraform test` by default + Terratest opt-in** |
| Q4 | Distribution | **Published npm package**, consumed via `npx projen new --from projen-terraform` |
| Q5 | Upgrade scope | **Both** tool versions and provider pins |
| Q6 | Default provider | **AWS** (`hashicorp/aws ~> 5.0`), overridable via options |
| Q7 | Remote state backend | **Scaffold `backend.tf` config only** (S3 + DynamoDB lock), no provisioning |
| Ext | Security Baseline | **Enabled** (blocking) |
| Ext | Property-Based Testing | **Partial** (pure functions + serialization round-trips only) |
| Ext | Resiliency Baseline | **Enabled** (directional design-time guidance) |

## Functional Requirements

### FR-1: Custom projen project type
- **FR-1.1** Provide a `TerraformProject` class extending projen's `Project`, authored with the component model.
- **FR-1.2** Expose typed options: `terraformVersion` (default `>= 1.6`), `providers` (default `{ aws: "~> 5.0" }`), `securityScanner` (default `both`), `enableTerratest` (default `false`), `backend` (default `s3` config-only).
- **FR-1.3** Be consumable via `npx projen new --from projen-terraform` (published npm package).
- **FR-1.4** Regenerate all managed files idempotently on `npx projen` (re-running produces no diff).

### FR-2: Managed governance/config files (projen-owned, header-marked)
- **FR-2.1** `versions.tf` — `required_version` + `required_providers` (AWS default), regenerated from options.
- **FR-2.2** `.tflint.hcl` — tflint config with sensible ruleset.
- **FR-2.3** tfsec config and checkov config (both scanners).
- **FR-2.4** `.terraform-docs.yml` — terraform-docs injection config.
- **FR-2.5** `backend.tf` — S3 + DynamoDB lock backend, **commented/templated**, no provisioning.
- **FR-2.6** Every managed file carries the projen "do not edit — edit .projenrc.ts" header.

### FR-3: Scaffolded user-owned files (created once, not regenerated)
- **FR-3.1** `main.tf`, `variables.tf`, `outputs.tf` scaffolds created only if absent; never overwritten.
- **FR-3.2** `README.md` with terraform-docs injection markers.
- **FR-3.3** `.gitignore` excluding `.terraform/`, `*.tfstate*`, `*.tfvars`, `crash.log`.

### FR-4: projen tasks (mirror CDK build pipeline)
- **FR-4.1** `fmt` → `terraform fmt -recursive`.
- **FR-4.2** `lint` → `tflint --recursive`.
- **FR-4.3** `validate` → `terraform validate`.
- **FR-4.4** `security` → run tfsec **and** checkov (both blocking).
- **FR-4.5** `docs` → `terraform-docs` regenerate into README markers.
- **FR-4.6** `test` → native `terraform test`; include Terratest invocation when `enableTerratest`.
- **FR-4.7** `build` → composite task running fmt(check)→validate→lint→security→docs→test in order.

### FR-5: GitHub Actions trio (projen-generated, mirror CDK repo shapes)
- **FR-5.1** `build.yml` — `ubuntu-latest`, `actions/checkout@v5`, install Terraform + tools, run `npx projen build`, then **self-mutation** detection (diff → `repo.patch` artifact → dependent job applies & pushes via `PROJEN_GITHUB_TOKEN`).
- **FR-5.2** `upgrade.yml` — `schedule: cron 0 0 * * *` + `workflow_dispatch`; upgrade **tool versions and provider pins**; open auto-PR via `peter-evans/create-pull-request@v7`.
- **FR-5.3** `pull-request-lint.yml` — `amannn/action-semantic-pull-request@v6`, types `feat`/`fix`/`chore`, `requireScope: false`.
- **FR-5.4** All three carry the projen "Generated by projen" header.

### FR-6: Test harness
- **FR-6.1** Generate a sample `tests/*.tftest.hcl` for native `terraform test`.
- **FR-6.2** When `enableTerratest`, scaffold a Go test module and wire it into `test`/CI.
- **FR-6.3** The project type's own synthesis logic is unit-tested with Jest (mirrors CDK repo testing its stacks).

## Non-Functional Requirements

### NFR-1: Consistency with CDK repos
- Use Node.js 22, npm, TypeScript. The three workflows must be behaviorally identical in shape to the reference CDK repo's `build`/`upgrade`/`pull-request-lint`.

### NFR-2: Idempotent synthesis
- `npx projen` is deterministic; re-running yields zero diff. CI self-mutation catches any drift (regenerated docs/fmt) and fails the build until committed.

### NFR-3: Security (extension — Security Baseline, blocking)
Applicable rules for this dev-tooling project:
- **SECURITY-06 (least privilege):** generated GitHub Actions tokens/permissions scoped minimally; `contents: write` only where self-mutation requires it.
- **SECURITY-10 (supply chain):** all tool/provider versions **pinned** (no `latest`); lock file (`package-lock.json`) committed; CI actions pinned to versions/tags as the CDK repo does; scanners (tfsec+checkov) act as the IaC vulnerability gate.
- **SECURITY-13 (integrity):** self-mutation push uses `PROJEN_GITHUB_TOKEN` secret (never plaintext); CI pipeline definitions are projen-managed and auditable.
- **SECURITY-09 (misconfiguration):** generated `.gitignore` prevents committing state/secrets; backend scaffold blocks public access by default.
- Rules N/A (no runtime app surface in the tool itself): SECURITY-01 partial (applies to *generated* backend guidance), 02, 03, 04, 05, 08, 12, 14, 15 — marked N/A for the project-type code; SECURITY-07 applies as guidance the scaffold encourages.

### NFR-4: Property-Based Testing (extension — Partial)
- PBT applies to **pure functions / serialization round-trips** only: the HCL renderers (`renderVersionsTf`, `.tflint.hcl` renderer, etc.) should have property tests asserting round-trip/idempotency (e.g. rendered HCL re-parses, regeneration is stable). CRUD/glue code exempt.

### NFR-5: Resiliency (extension — directional)
- Design-time guidance only; for a scaffold tool the relevant practices are: deterministic/reproducible builds, CI failure observability (self-mutation surfacing drift), and graceful handling when tools (terraform/tflint/scanners) are absent in CI (fail with a clear message, not a silent pass).

### NFR-6: Usability
- Zero-to-passing-CI in < 5 minutes via `npx projen new`. Sensible defaults; every option documented.

## Out of Scope (MVP)
CDKTF; JSII multi-language packaging; Terraform Cloud/Spacelift/Atlantis; remote-state provisioning; terragrunt/multi-env orchestration; OPA/Conftest/Sentinel; live drift detection. (See `inputs/vision.md` for phase targets.)

## Key Risks / Open Items
- projen has **no native HCL project type** — the HCL files and tooling generators are custom components; the self-mutation pattern must be reproduced rather than inherited.
- The generated repo requires a **Node toolchain** to run projen even though it's otherwise a Terraform repo (accepted, as with CDK repos).
- tfsec is being **folded into Trivy** upstream — running "both" tfsec + checkov should track tfsec's maintenance status (revisit in `upgrade`).
